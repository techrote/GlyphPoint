# GlyphPoint 2.0.0-rc.1

This candidate turns the limitations from the first quality audit into implemented recovery, rendering, interchange, and editing improvements. The maintained entry point remains **GlyphPoint-RC.html**. Download and extract the candidate ZIP, then open that file in a current browser; no runtime installation or server is required.

## What's new

- Automatic IndexedDB recovery checkpoints after edits, explicit recovery selection/deletion, separate identities for simultaneous tabs, finite archive/queue budgets, and visible storage failure states.
- Direct project-file writes when the browser offers the File System Access picker, Save As, and an explicit JSON download fallback. Download requests and completed writes have distinct status and dirty-state behavior.
- Viewport Canvas2D rendering with bounded animation-frame work, no DOM element per artwork cell, and scroll/zoom-aware hit testing. Flood fill and resize/skew use cancellable worker jobs with a cooperative fallback and atomic revision-checked commits.
- `glyphpoint-v3` projects: one complete grapheme per cell, up to 32 code points, plus optional per-cell foreground and background overrides. v1/v2 projects still open with their prior palette-based appearance.
- Embedded DejaVu Sans Mono regular/bold/italic faces; complete-field PNG export and prepared print images. Native HTML exports include cell styling, embedded fonts, and editable project data.
- Broader inert external HTML/CSS import: inherited colours, simple selectors/cascade, named/RGB/HSL colours, alpha compositing, and supported typography. External resources remain inactive.
- Expand, Reject, and explicit Clip policies for placement; default expansion for paste/move/text/selected rotations; inverse-sampled sequential skew with validated bounds.
- A keyboard-operable field, live cell descriptions, Shift selection, keyboard painting/erasing/text entry, readable text view, larger touch controls, pan mode, and an accessible secondary-glyph choice.
- Updated comprehensive manual, new-user guide, agent/RAG reference, source modules, developer instructions, platform acceptance records, reproducible package/checksums, and bounded multi-platform CI.

## Compatibility and limits

The field remains bounded to 4,096 cells per axis and 1,048,576 cells overall; projects/imports have a 16 MiB budget, and the palette includes at most 4,096 entries. Recovery is browser-local, with up to 12 documents and 32 MiB of payloads; project files remain the portable backup.

Grapheme interpretation follows the browser's Unicode segmentation. Missing font coverage can still use system fallback; use PNG for a fixed rendered result. The editor implements a bounded CSS subset and a discrete cell model, not arbitrary webpage rendering or continuous raster geometry. Explicit Clip mode discards overflow, and shrinking Properties asks before discarding nonempty/styled cells.

Hosted browser/OS checks and emulated touch tests are described in [platform qualification](../docs/platform-qualification.md). Physical Windows/macOS/iOS/Android workflows and screen-reader acceptance require their separate records; no physical certification is implied by this candidate.
